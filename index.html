Never missing a settlement cycle

Settlement windows are fixed and unforgiving, so the retry mechanism is the part that matters. I designed it end to end. Since launch, no cycle has been missed. Uptime sits at 99.9%, with the only planned downtime falling inside a maintenance window when merchant traffic is idle.

CPU-intensive jobs run on AWS Batch over Fargate, scheduled through EventBridge and provisioned programmatically with Boto3, so heavy work never competes with the application servers for headroom.

  • AWS Batch · Fargate
  • EventBridge · Boto3

A refund module the network doesn't provide

NPCI doesn't offer refunds natively on eNACH. Merchants still need them. So we built the capability in-house — I ran the proof of concept, wrote the design document, and drove it through cross-functional review to production.

The hard part isn't issuing the refund. It's that a refund has to reason about a debit that may still be in flight, already settled, or partially failed, and it has to stay reconcilable against a network that has no opinion about any of it.

  • Design doc · POC · cross-functional
  • Not available upstream
